# 📊 Data Directory

This directory contains all datasets and data resources used throughout the **AI-Based Phishing Detection Framework**. It includes the original datasets, processed feature datasets, scan history logs, and schema documentation used during model training and prediction.

---

# 📂 Directory Structure

```
data/
├── 📁 raw/
│   ├── legitimate.csv
│   ├── phishing.csv
│   └── master_dataset.csv
│
├── 📁 processed/
│   ├── cleaned_dataset.csv
│   └── features_dataset.csv
│
├── 📁 history/
│   └── scan_history.csv
│
├── data_schema_design.txt
└── README.md
```

---

# 📁 Folder Description

## 📂 raw/

Contains the original datasets collected for training the phishing detection model.

Files in this directory are considered **read-only** and serve as the primary source of data before preprocessing.

### Files

- **legitimate.csv** — Collection of legitimate website URLs.
- **phishing.csv** — Collection of phishing website URLs.
- **master_dataset.csv** — Combined dataset containing both legitimate and phishing URLs.

---

## 📂 processed/

Contains datasets generated after preprocessing and feature extraction.

These files are directly used for machine learning model training and evaluation.

### Files

- **cleaned_dataset.csv** — Cleaned dataset after removing inconsistencies and duplicates.
- **features_dataset.csv** — Dataset containing extracted numerical features used by the machine learning model.

---

## 📂 history/

Stores scan history generated during application execution.

Each prediction made through the Flask API is automatically recorded in this directory.

### Files

- **scan_history.csv** — Timestamped log of scanned URLs, predictions, confidence scores, and risk levels.

---

## 📄 data_schema_design.txt

Defines the expected data structure used throughout the project.

The schema specifies:

- Expected feature names
- Data types
- Validation rules
- Dataset structure
- Storage guidelines

This document serves as the reference blueprint for dataset consistency.

# ✅ Data Integrity

The framework maintains data consistency through several validation steps:

- Removal of duplicate records
- URL normalization
- Feature validation
- Missing value handling
- Schema consistency checks
- Standardized feature naming
- Consistent numerical feature extraction

These validation steps help ensure reliable model training and accurate phishing detection.

---

# ⚠️ Notes

- Do not modify files inside the **raw/** directory after collection.
- The **processed/** directory should only contain datasets generated by the preprocessing pipeline.
- The **history/** directory is automatically updated whenever a URL is analyzed through the application.
- Keep the dataset schema synchronized with the feature extraction module to avoid inconsistencies during prediction.
